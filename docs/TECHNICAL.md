# 기술 설명

PS1 일본판 『Helix フィアー エフェクト』(SLPS-03340~03343, 4장)을 한글화하면서 알아낸 데이터 구조와 패치 방법을 정리합니다. 주소는 모두 원본 디스크 기준입니다.

## 디스크와 파일

- 디스크마다 BIN/CUE 1트랙(MODE2/2352)입니다. ISO9660 파일 시스템을 읽어 파일 단위로 바꿉니다(`tools/iso.py`, `tools/disc.py`).
- 바꾼 파일은 같은 LBA에 다시 쓰고, 섹터마다 EDC/ECC를 다시 계산합니다(`tools/cdsec.py`). 모든 파일이 원래 섹터 수 안에 들어가므로 이미지 크기는 원본과 같습니다.
- 바꾸는 파일(디스크마다 같은 구성):

| 파일 | 내용 |
| --- | --- |
| `SLPS_033.4x` | 실행 파일. 확장 글리프 렌더러 패치 |
| `FONT2.WAD` 안 `FONTLG.FNT` | 게임 글꼴(4bpp TIM 256×256) |
| `ENV/?E.DB`, `ENV/*ENV.WAD` 안 `.DB` | 아이템·무기·메시지 문자열 표 |
| `*ENV.WAD`·`IFACE/TITLEE.WAD`·`IFACE/LEVSEL.WAD` 안 `SNAMEE.SNA` | 장면(장소) 이름 |
| `IFACE/TITLEE.WAD`·`IFACE/SWAPE.WAD` 안 `FONTTITJ.FNT` | 타이틀·디스크 교체 화면 글꼴(16×16) |
| `IFACE/TITLEE.WAD` 안 `*.BKG` | 메뉴 그림 글자(TIM) |
| `OVERLAY/GSHELL.OVR`, `OVERLAY/SWAP.OVR` | 타이틀·옵션·메모리 카드·디스크 교체 화면 문자열 |
| `*.SID`, `ABG?/ABG?.FLX` | 동영상(STR v2). 자막 부분만 다시 인코딩 |

WAD는 `[이름, 오프셋, 종류, 크기]` 항목이 이어진 묶음 파일이고(`tools/wad.py`), 항목 크기를 바꾸지 않고 내용만 교체합니다.

## 게임 글꼴과 문자 코드

- 게임 문자열은 1바이트 코드입니다. `` ` ``(0x60)는 ASCII, `@`(0x40)·`~`(0x7E)·`^`(0x5E)는 일본어 1·2·3페이지로 바꾸는 전환 코드이고, 뒤따르는 바이트가 그 페이지의 글리프 번호입니다(`tools/jtab.py`).
- `FONTLG.FNT`는 12×12 칸 16열 시트입니다. 일본어 영역(행 6~20)과 오른쪽 빈 열(x 192~239)을 비우고 한글을 그렸습니다.
- 한글은 **266자**가 필요합니다. 1~3페이지의 남는 코드 슬롯을 먼저 쓰고, 모자란 글자는 새 4페이지 코드(0x80~0xD3, 84자)로 넣었습니다. 4페이지 글자는 시트 오른쪽 열(x 192~, 4열)에 그립니다.
- 원래 렌더러는 0x80 이상 바이트를 건너뜁니다. 실행 파일 `0x8004AAD0`의 분기를 빈 영역 `0x8007B500`으로 보내, 0x80 이상이면 오른쪽 열의 칸 좌표를 계산해 원래 그리기 루틴(`0x8004AB70`)으로 돌아가게 했습니다(`tools/ui.py` `exe_patch`).
- 글자는 갈무리11(12px)을 원본 글꼴의 밝기 단계에 맞춰 그렸습니다.

## 문자열 표

- `?E.DB`에는 아이템·무기·메시지 문자열 표가 있고, 각 표는 기준 주소에서의 u16 오프셋 배열을 가집니다(`tools/db.py`). 번역문을 표 영역 안에서 다시 배치하고 오프셋을 고칩니다(`tools/dbw.py`). 다음 섹션 시작을 넘으면 빌드가 멈춥니다.
- `SNAMEE.SNA`는 `[그룹 수][그룹 오프셋]`, 그룹마다 `[개수][(id, 문자열 오프셋)]`, 그 뒤 문자열 영역 구조입니다. 문자열 영역을 다시 채우고 오프셋을 고칩니다(`tools/sna.py`).
- 번역 파일 `text/ui_ko.tsv`, `text/sna_ko.tsv`의 키는 일본어 원문(UTF-8)의 SHA-1 앞 16자리입니다. 빌드할 때 원본 디스크에서 읽은 원문을 해시해 찾으므로, 저장소에는 원문이 없습니다.

## 타이틀·디스크 교체 화면

- `FONTTITJ.FNT`(16×16, 코드 0x20~0x7F)는 원래 영숫자와 일부 일본어만 있습니다. 화면 문자열에 쓰인 한글 62자를 코드 0x3A부터 배정하고 나눔스퀘어네오 Bd로 그렸습니다(`tools/title.py`).
- `GSHELL.OVR`, `SWAP.OVR` 문자열은 원래 자리(뒤 0 패딩 포함) 안에서 바꿉니다(`text/title_ko.tsv`: 파일·오프셋·번역).
- 메뉴 그림 글자 `*.BKG` 30종은 원본 회색 팔레트만 써서 나눔스퀘어네오 ExtraBold로 다시 그렸습니다. 아이콘이 있는 그림은 글자 영역만 바꿉니다(`tools/bkg.py`).

## 동영상 자막

일본판 동영상은 자막이 화면 오른쪽에 세로로 영상에 박혀 있습니다. 그래서 프레임을 디코드해 자막을 지우고 한글을 그린 뒤, 바뀐 매크로블록만 다시 인코딩합니다.

1. **스캔**(`tools/scan.py`): 스트림 전체를 디코드해 프레임별 흰 글자 마스크를 저장합니다. 디코더는 numba로 만든 STR v2 디코더입니다(`tools/fmv.py`, `tools/mdec.py`).
2. **구간 검출**(`tools/segs.py`, `tools/jseg.py`): 같은 글자 마스크가 유지되는 프레임 범위를 자막 구간으로 잡습니다. 구간 정보(`text/fmv/<TAG>.json`)는 프레임 번호와 자막 상자뿐이고, 원문은 없습니다.
3. **적용**(`tools/fmvapply.py`, `tools/sub.py`): 구간마다 자막 마스크를 넓혀 inpaint로 지우고, 번역(`text/fmv/<TAG>_ko.tsv`)을 세로쓰기로 그립니다. `/`는 줄(세로 열) 나눔, `<…>`는 노란 강조입니다. 바뀐 매크로블록만 원래 양자화 단계로 다시 인코딩해, 프레임이 원래 섹터 수 안에 들어가게 합니다. 들어가지 않으면 양자화를 높이고(`lowq`), 그래도 안 되면 그 프레임은 원본 그대로 둡니다(`fail`).
4. 처음 검출에서 놓친 구간(키 1000 이상)은 앞뒤 프레임에서 자막이 계속 보이는 동안 구간을 늘립니다(최대 200프레임, 다른 구간과 겹치지 않게).

| 디스크 | 스트림 | 구간 | 교체 프레임 | 원본 유지 프레임 |
| --- | --- | --- | --- | --- |
| 1 | OPEN.SID, BOOT.SID, ABGA, ABGC | 292 | 23,564 | 5 |
| 2 | ABGB, ABGH | 453 | 33,960 | 11 |
| 3 | ABGI, ABGE | 301 | 25,076 | 8 |
| 4 | ABGD, ABGF | 239 | 20,359 | 5 |

## 화면 확인

`tools/emu.py`는 DuckStation을 창 밖에 띄우고 GDB 서버로 메모리를 읽고 쓰며, 창 메시지로 키를 보내고 스크린샷을 찍습니다. 동영상 확인은 1번 디스크 이미지 사본의 `LOGO.SID` 디렉터리 항목을 확인할 스트림으로 바꿔 부팅 직후 재생되게 하는 방법을 썼습니다.
